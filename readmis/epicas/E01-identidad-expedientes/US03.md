# US03 — Acceder al portal y consultar datos propios

**Épica:** [E01 — Identidad y expedientes](README.md)  
**Prioridad:** Alta  
**Dependencias funcionales:** US01, US02; datos de US04–US12 conforme existan  
**Reglas:** `NEG-05`, `NEG-06`, `NEG-08`, `NEG-38`

## Historia de usuario

**Como** cliente con cuenta activa, **quiero** iniciar sesión y ver únicamente mis motocicletas y su información asociada, **para** conocer historial, mantenimiento, garantías, citas y avance de taller.

## Flujo principal

1. El cliente se autentica con identificador @follow.motors y contraseña.
2. La API resuelve la identidad del cliente y verifica su estado activo.
3. Las consultas filtran motos y registros por propietario en el servidor.
4. Angular muestra secciones disponibles o estados vacíos sin inventar datos.

## Criterios de aceptación

1. El cliente ve datos de motos, historial, próximos mantenimientos, garantía, citas y estado de trabajos cuando hay registros.
2. Una cuenta sin moto ni servicios inicia sesión y ve una pantalla vacía útil.
3. Alterar un ID para intentar consultar una moto ajena no revela datos.
4. Una cuenta desactivada no obtiene consultas privadas.
5. Angular no contiene credenciales de MySQL ni escribe directamente expedientes.
6. Las funcionalidades de reserva y cancelación se delegan a sus historias, no a consultas genéricas sin permisos.

**Alternativas y errores a probar:** Cliente sin motos, sesión vencida, acceso a ID de otro propietario.

## Tarjetas CRC (7)

Cada fila es una **tarjeta CRC**: una clase candidata, su responsabilidad y sus colaboradores. Los nombres son analíticos, no archivos obligatorios; las clases compartidas se reutilizan entre historias y pueden consolidarse.

| Clase candidata | Responsabilidades | Colaboradores |
| --- | --- | --- |
| `SesionCliente` | Mantener identidad autenticada y vigencia del acceso. | CuentaCliente, AutorizadorPropiedad |
| `AutorizadorPropiedad` | Verificar que cada recurso consultado pertenece al cliente. | SesionCliente, RepositorioMotocicletas |
| `ConsultaExpediente` | Reunir lectura privada de moto, citas, servicios y garantías. | AutorizadorPropiedad, RepositorioServicios |
| `RepositorioMotocicletas` | Entregar motos vinculadas sin exponer registros ajenos. | ConsultaExpediente, AutorizadorPropiedad |
| `RepositorioServicios` | Consultar historial y estados asociados a motos autorizadas. | ConsultaExpediente, HistorialServicio |
| `HistorialServicio` | Ordenar datos históricos visibles al propietario. | RepositorioServicios, ConsultaExpediente |
| `PortalClienteViewModel` | Presentar consultas y estados vacíos, sin decidir permisos. | ConsultaExpediente, SesionCliente |

## Validación técnica esperada

- **Pruebas unitarias:** reglas y decisiones aplicables a esta historia, sin depender de MySQL real.
- **Prueba de integración:** API, autorización y persistencia donde exista cambio de estado.
- **Demostración:** flujo correspondiente desde escritorio C# o Angular, con datos ficticios y sin afirmar implementación hasta tener evidencia.
